# 주행 중 평가 수집과 화면 제한

## 수집 수명과 저장

`TripService`는 사용자가 주차 중 자동 기록을 켠 뒤 앱이 준비한 대기 상태와 주행 수집기를 소유합니다. `EvaluationController`는 Activity나 ViewModel 수명과 분리되어 있으며, 서비스의 Main coroutine scope에서 수집 상태를 직렬화합니다. 홈 이동·화면 중지·Activity 재생성은 실제 주행 수집을 취소하지 않습니다. 진단용 합성 시나리오 감시만 기존처럼 진단 화면이 중지될 때 해제합니다. 사용자 홈과 진단 화면은 제한이 활성화되면 주행 화면으로 이동하고 주차용 내용을 즉시 숨깁니다.

- 사용자 홈에서 **자동 기록 켜기**를 설정합니다. 기본값은 OFF이고 설정은 앱 재실행 후에도 유지됩니다. 앱이 보이는 상태에서 대기 서비스를 준비하며, D단 관측 시 버튼 없이 기록을 시작합니다.
- R·N단과 D단 정차는 같은 세션을 유지합니다. P단이 연속 10초 유지되면 평가·저장합니다. 10초 전에 D·R·N단으로 바뀌거나 기어 정보가 끊기면 P단 대기를 취소합니다.
- 주차 중 **자동 기록 끄기**를 선택하면 진행 중 기록을 저장하고 대기 서비스도 종료합니다. 꺼진 설정도 재실행 후 유지됩니다.
- 사용자 연습은 최대 10분이며, 기존 진단 버튼의 30초 수집도 같은 서비스에서 실행됩니다.
- 자동 기록 대기·수집 알림과 `specialUse` 포그라운드 서비스 유형·용도 설명을 선언했습니다. 다른 유형으로 수집 목적을 위장하지 않습니다.
- 설정 변경은 플랫폼 UX 상태와 P단을 확인한 뒤 허용합니다. 센서 권한 없이 자동 대기나 수집을 시작하지 않습니다. 중복 시작 요청은 기존 수집을 교체하지 않습니다.
- 종료 시 센서 구독을 해제하고 평가한 뒤 원본을 `files/sensor-traces/<sessionId>.json`과 호환용 `latest.json`에 원자적으로 저장합니다. 동일 세션의 평가를 기존 durable outbox에 저장한 후에만 `SAVED` 상태를 표시합니다.
- 저장 실패는 완료로 표시하지 않습니다. 업로드 성공 여부는 로컬 저장 완료와 별개이며, 기존 WorkManager 재시도·설치 인증·중복 방지 정책을 유지합니다.
- 자동 기록이 켜진 상태에서는 저장 후에도 대기를 유지해 다음 D단 전환을 감지합니다. 설정을 끄면 구독·coroutine·알림을 해제합니다. 화면 복귀가 저장 조건은 아닙니다.

현재 범위는 프로세스가 살아 있는 동안의 수집 연속성입니다. 강제 종료·프로세스 사망·재부팅 후 원시 입력 복원이나 끊긴 주행 자동 재개는 포함하지 않습니다. 중단된 세션을 완료 평가로 꾸미지 않으며, 이미 완료되어 outbox에 저장된 기록은 기존 방식으로 유지됩니다. 10분 상한과 원시 데이터 상한은 장시간 기록 정책을 대신하지 않습니다.

## 주차용·주행용 화면

`DrivingAccess`는 공식 `CarUxRestrictionsManager` 구독과 현재 기어를 함께 읽습니다. 제한 여부를 속도만으로 추정하지 않습니다. UX 서비스 미연결·기어 미확인·주행 제한·개별 제한 플래그가 있으면 설정을 닫는 보수적인 정책입니다. D단 정지 상태도 P단으로 취급하지 않습니다.

- `MainActivity`: 주차 시에만 진입하는 계정 연결·QR·연습 준비 화면. DO를 선언하지 않습니다. 앱 내부에서도 주차 확인 전에는 기능을 숨깁니다.
- `DiagnosticsActivity`: debug 전용, DO를 선언하지 않아 주행 중 플랫폼 제한을 유지합니다.
- `DrivingActivity`: 앱 런처의 단일 작업 진입점이며 주차 상태에서는 사용자 홈으로 연결합니다. Pleos 런처의 작업 단위 제한에 맞춰 주행용 화면을 작업 진입점으로 사용합니다. 이 Activity에만 `distractionOptimized=true`를 선언합니다. 주행 중에는 기록 상태와 주차 후 확인 안내 두 줄만 표시합니다. 점수·센서 수치·스크롤·QR·설정·개발 버튼을 표시하지 않습니다. 주차가 확인되면 P단 10초 후 저장 안내와 설정/홈 진입 버튼을 제공합니다. 진단용 수동 수집에만 기존 종료 버튼을 유지합니다.

이는 에뮬레이터에서의 제한 연동 구현입니다. 실제 Pleos Market의 앱 분류·심사 승인, 양산 차량별 적합성 확인까지 완료했다는 의미는 아닙니다.

## 자동 검증

```powershell
.\infra\pleos\test-driving-service.ps1
# 이미 최신 APK를 설치했다면:
.\infra\pleos\test-driving-service.ps1 -SkipBuild
```

Windows의 `emulator-NNNN`만 대상으로 합니다. 물리 차량은 거부합니다. 기본 Virtual Console(8088)의 다른 탭은 모두 닫고, P단·속도 0에서 시작합니다. 테스트가 자체 heartbeat 연결을 유지하며, 기존 지역/UX 정책을 끄거나 VHAL 제한을 강제 해제하지 않습니다.

테스트는 로컬 `compose.dev.yaml`의 web만 잠시 중지합니다. 실제 사용자 설정으로 자동 기록을 켜고 앱을 재실행한 뒤 다음을 확인합니다.

1. D단 자동 시작 → R단 → N단 → D단 24km/h 주행 → 짧은 P단 → D단 재개 → HOME으로 Activity STOPPED → P단 복귀까지 동일한 세션과 증가하는 수신 수.
2. D단에서 플랫폼의 `requiresOptimization=true`, 제한 플래그, 기어가 실제로 관측되는지 확인.
3. 주행용 화면이 플랫폼에 차단되지 않으며 주차용 버튼을 노출하지 않는지 확인. 접근성 트리 외에도 캡처의 실제 주행 화면 바탕색을 확인해 런처의 차단 오버레이를 성공으로 오인하지 않습니다.
4. 화면 중지 구간의 원시 SDK 속도와 조향각 수신을 지시한 입력 시간대와 비교.
5. 짧은 P단에서는 종료하지 않으며, 마지막 P단 연속 10초 후 버튼 없이 세션별 원본과 `PENDING` outbox를 저장하고 평가 내용이 같은지 확인.
6. 서버 복구 후 `SENT` 상태, 서버에 보존된 평가와 세션당 기록 한 건을 확인. 다음 D단에서 새 세션이 생기는지, 주차 중 설정을 끄면 저장·서비스 해제되는지, 다시 앱을 열어도 OFF를 유지하고 D단에서 기록하지 않는지 확인.

종료·실패·Ctrl+C 시 서버를 복구하고 기어·속도·페달·조향·방향지시등을 초기화합니다. 실패 시 테스트 소유 수집이 남아 있으면 debug 앱을 종료합니다. 기존 기록과 설치 인증 정보는 삭제하지 않습니다. 생성된 LIVE 평가 기록은 에뮬레이터 시연 기록으로 남습니다.

결과는 `apps/pleos/driving-evaluation/build/scenarios/driving-service/result.json`, 원본은 `latest.json`, 화면 증거는 `drive-restricted.png`와 `restricted-window.xml`, 화면 중지 증거는 `background-activities.txt`에 저장합니다. 설치 비밀 키는 결과에 출력하지 않습니다.

순수 회귀 검증은 기존 CI의 `test_*.py` 탐색에 포함됩니다. 실제 Pleos 에뮬레이터 통합 실행은 Windows 환경에서 별도로 실행합니다. 일반 CI에서 에뮬레이터 통합 검증을 수행한 것처럼 보고하지 않습니다.

## 기존 진단 경로

진단용 30초 수동 센서 수집은 별도로 유지합니다. 자동 기록을 끈 상태에서 실행하며 사용자 홈에는 수동 시작 버튼을 제공하지 않습니다. 엔진 평가 규칙과 업로드 API 계약은 변경하지 않습니다.


## 자동 기록 검증 결과

- Android 앱 단위 테스트 26개(자동 세션 규칙 12개 포함), Python 회귀 테스트 34개 통과. debug APK와 Android Lint 오류 0건 확인.
- D단 정지 13개 → R단 62개 → N단 109개 → D단 주행 148개 → 짧은 P단 167개 → D단 재개 182개 → 화면 중지 226개 → P단 복귀 252개의 속도 관측을 동일 세션에서 확인했습니다. 정지 상태에서 변화 콜백이 없을 수 있으므로 R·N단은 독립적인 실제 기어 원본 관측도 함께 확인합니다.
- 최종 P단 시작에서 원본 종료 시점까지 10,356ms였으며, 10초 이전에는 완료 기록을 저장하지 않았습니다. 짧은 P단에서 D단으로 돌아가면 대기가 취소됐습니다.
- 자동 ON 설정을 켠 뒤 앱 강제 종료·재실행 시 대기 복원, 다음 D단의 별도 세션 생성, 주차 중 OFF 시 진행 기록 저장·서비스 해제, OFF 설정 재실행 유지와 D단 기록 미시작을 확인했습니다.
- 오프라인 PENDING 저장, 서버 복구 후 SENT 전환과 원본 평가 일치, 세션당 서버 기록 한 건도 확인했습니다.
- 기어의 실제 발생 시각(`providerTimestampMs`)과 늦게 조회되는 수신 시각을 구분해 검증합니다. 오래된 기어 원본이 전환 증거로 통과하지 않는 부정 테스트를 포함합니다.
