# 주행 평가 엔진 v0.4

`apps/pleos/driving-evaluation`은 Android·Pleos SDK·서버에 의존하지 않는 Kotlin/JVM 모듈입니다. 차량 앱이 관측 데이터를 전달하면 같은 입력과 설정에 대해 같은 평가 결과를 반환합니다. 주행 후 재생 평가가 기본이며, 실시간 입력도 수집한 구간을 같은 엔진에 전달할 수 있습니다.

고정 시연 시나리오, 실제 에뮬레이터 입력 자동화, 기록 재생 및 CI 실행은 [시나리오 자동화 문서](driving-evaluation-testing.md)를 참고합니다.

위치·지도 기반 행동 검출, 입력 품질, 이벤트 묶음 및 한국어 복습 피드백은 [v0.4 구현 안내](driving-practice-analysis.md)를 참고합니다. 아래 v0.1~0.3 검증 기록은 해당 시점의 결과입니다.

## 구현한 범위

| 항목 | 입력 | 결과 |
|---|---|---|
| 제한속도 대비 속도 관리 | 속도, 현재 매칭 도로, 그 도로의 제한속도·유효기간 | 평가 가능한 시간·거리, 기준 초과 비율, 지속 이벤트 |
| 가감속 패턴 | 실제 생성 시각이 있는 연속 속도 | 시간 간격을 반영한 가속도, 평균 절대 가속도, 급격한 변화 복습 이벤트 |
| 회전 시 방향지시등 | 독립적으로 확인된 완료 회전, 방향지시등 선택 상태 | 충분한 준비, 준비 시간 부족, 미사용·반대 방향·해제 관측 |
| 조향 조작 패턴 | 조향각, 시각 기준, 관측 공백 | 평균/최대 변화 속도, 급조향·반복 방향 반전 복습 이벤트 |
| 복합 맥락 | 조향/감속 이벤트와 속도·기어·브레이크·방향지시등·크루즈 상태 | 정차·후진·신호 동반·제동 동반·반복 보정 후보 및 누락 근거 |
| 차로 유지·신호 대응·차간거리 | 환경 데이터와 별도 평가 규칙 필요 | `NOT_ASSESSED`와 제외 사유 |

후자의 세 항목은 아직 구현하지 않았습니다. 조향각만으로 실제 차로 위치를 판단하거나, 자차 속도만으로 차간거리를 대신 평가하지 않습니다. 차로 변경 추정·회전 검출 자체·지도 매칭·신호/객체 추적도 후속 모듈입니다. 현재 회전 평가는 확인된 행동을 입력받는 규칙이며 회전을 자동으로 검출했다는 의미가 아닙니다.

엔진은 **종합 운전 점수, 위반 확정, 급제동 원인, 운전자의 숙련도**를 반환하지 않습니다. 모든 이벤트는 `reviewOnly=true`인 복습 관측입니다. 평가 불가 구간은 0점 또는 만점으로 대체하지 않습니다. 저크 및 미세한 부드러움 점수는 보정·검증 전까지 보류합니다.

## 모듈과 입력 계약

```text
AAOS·Pleos·지도 어댑터 (app)
  → DrivingSession / Observation
  → DrivingEvaluationEngine.evaluate()
  → EvaluationReport
  → 개발용 결과 화면 / 향후 주행 기록 저장·동기화
```

- `DrivingData.kt`: 입력·관측 가용성·실험용 규칙 설정.
- `DrivingEvaluationEngine.kt`: 신선도 및 구간 처리, 세 가지 평가 규칙.
- `EvaluationReport.kt`: 지표·평가 범위·보류 사유·근거 이벤트.
- `SteeringEvaluation.kt`: 조향 미분·유의미한 방향 반전과 표본 품질 검사.
- `SensorTelemetry.kt`: 공개 읽기 정책, 센서 가용성·원시 맥락 계약, 복합 맥락 판별.
- `Replay.kt`: 명시적으로 합성된 12초 입력과 콘솔 재생 도구.

시간은 **하나의 세션에서 동일한 기준의 monotonic millisecond**를 사용합니다. UTC는 이 엔진의 계산 시각으로 사용하지 않습니다. 단위는 속도 m/s, 가속도 m/s², 거리 m입니다. 다른 센서의 값마다 관측 생성 시각이 별도로 있어야 합니다. 미래 관측을 과거에 소급 적용하거나 결측 구간을 선형 보간하지 않습니다.

각 스트림은 세션 범위 안에서 시각이 엄격하게 증가해야 합니다. 중복·역순 또는 범위 밖 시각이 있으면 해당 스트림을 보류합니다. `null`, 가용성 상실, 오래된 값, NaN·Infinity, 범위 밖 값은 실제 0 또는 방향지시등 OFF와 다릅니다. 후진 속도는 원시 부호를 보존하며 이 버전의 전진 평가에서 제외합니다.

`speedGaps`는 수집 오류·서비스 단절을 나타내는 별도 구간입니다. 센서 시각이 없는 오류에 가짜 속도 표본을 만들지 않습니다. 공백을 가로질러 미분하거나 속도 초과 이벤트를 이어 붙이지 않고 필터 상태도 재설정합니다. 공백이 끝나도 이전 표본을 다시 살리지 않으며, 공백 종료 시각 이후의 새로운 표본이 필요합니다.

`RoadContext`는 현재 매칭 도로와 제한속도 적용 도로가 같아야 합니다. 명시적인 `validUntilMs`와 관측 신선도를 모두 확인합니다. 실제 지도 어댑터는 도로 변경·지도 매칭 상실 시 컨텍스트를 즉시 무효화해야 합니다. 엔진 자체는 도로 매칭 결과의 진위를 검증할 수 없습니다.

방향지시등은 점멸 램프가 아니라 **선택 상태**(`LEFT`, `RIGHT`, `OFF`, `HAZARD`)로 정규화해야 합니다. 점멸 신호 또는 의미 미확인 입력은 평가하지 않습니다. 비상등도 맥락 없이 잘못된 사용으로 단정하지 않습니다.

회전에는 `MATCHED_ROAD_TRANSITION`과 `OBSERVED_HEADING_CHANGE`가 함께 필요합니다. 내비 안내나 방향지시등만으로는 실제 회전을 확인할 수 없습니다. 준비 구간의 관측이 완전하고 회전이 끝난 뒤에만 평가합니다. `turnDetectionComplete=true`는 독립된 회전 검출기가 전체 세션을 관측했다는 호출자의 명시적 선언입니다. 이 선언이 없는 빈 회전 입력은 미평가이며, 완전한 관측 결과 회전이 0건인 경우에만 `NO_OPPORTUNITY`입니다. 일부 확인된 회전만 있으면 그 회전은 평가하되 전체 항목은 `PARTIAL`입니다.

## 실험용 규칙 기본값

아래 값은 동작 검증용 설정이며 법적 기준·실차 보정값이 아닙니다. `EvaluationConfig`와 `ruleVersion`을 결과에 함께 남깁니다.

| 설정 | 기본값 |
|---|---|
| 속도 / 도로 / 방향지시등 최대 관측 나이 | 1초 / 2초 / 1초 |
| 속도 초과 후보 진입 / 이탈 | 제한속도 +5km/h 초과 / +4km/h 이하 |
| 속도 초과 후보 최소 지속 | 2초 |
| 가속도 계산 허용 표본 간격 | 50~500ms |
| 가속도 평활화 | 시간 간격에 따른 EMA, 시정수 300ms |
| 가속 / 감속 복습 이벤트 | +2.5 / -3.5m/s² 이상 크기, 0.5초 지속 |
| 비현실적인 속도 / 속도 변화 제외 | 100m/s 초과 / 절대 가속도 12m/s² 초과 |
| 회전 전 연속적인 방향지시등 준비 관측 | 3초 |

히스테리시스는 경계 진동에 따른 이벤트 분리를 줄입니다. 속도 이벤트 시간은 후보 진입부터 이탈까지이며, +4~5km/h 범위의 유지 구간이 포함될 수 있습니다. `excessiveMs`와 `excessiveTimeRatio`는 별도로 +5km/h를 초과한 실제 평가 가능 시간만 계산합니다. 미평가 시간은 비율의 분모에 넣지 않습니다. 최소 지속시간을 표본 개수로 환산하지 않습니다.

가감속 지표는 평활화한 속도 변화에서 산출합니다. 관측 단절, 부적합한 간격, 비현실적인 점프에서는 연속성을 끊습니다. 사건의 원인은 `unknown`으로 남으며 끼어들기에 대한 대응인지 운전 미숙인지 판단하지 않습니다. 정차 상태의 평균 가속도 0은 데이터 지표일 뿐 운전 기술이 검증됐다는 의미가 아닙니다.

## 실행과 검증

```powershell
# 순수 엔진 테스트와 합성 데이터 재생 (에뮬레이터 불필요)
.\infra\pleos\gradle.ps1 :driving-evaluation:test :driving-evaluation:run

# 앱 빌드·Lint
.\infra\pleos\gradle.ps1 :app:assembleDebug :app:lintDebug

# Windows 에뮬레이터 설치·실행
.\infra\pleos\install-windows.ps1 -SkipBuild
```

합성 재생은 12초 동안 속도 증가·감소와 확인된 좌회전을 주고 방향지시등을 OFF로 유지하는 시나리오입니다. 기본 설정에서 급가속, 지속 속도 초과, 급감속, 방향지시등 미사용 복습 이벤트가 생성됩니다. 이는 규칙과 입력 연결 검증이며 실차 검출 정확도 검증이 아닙니다.

## 앱의 실제 입력 확인

개발 화면의 `실제 센서 전체 30초 수집·분석`에서 차량 속도 권한을 요청합니다. `VehicleSpeedSource`는 `CarPropertyManager`의 `PERF_VEHICLE_SPEED`를 읽고, 하드웨어 생성 시각과 수신 시각을 구분합니다. 10Hz를 요청하지만 실제 설정 범위와 수신 간격을 따로 확인합니다. 권한 거절·미지원·서비스 오류는 관측 실패로 표시하며 가짜 0을 채우지 않습니다.

이 확인 화면은 전경에서 30초 동안 속도/조향각 각각 최대 2,000개를 수집하는 진단 기능입니다. 화면을 벗어나면 수집을 종료합니다. 시작 전 캐시 값은 제외하고, 중복 시각은 임의로 제거하지 않아 엔진의 품질 검사에 전달합니다. 방향지시등·브레이크·크루즈 등은 공개 SDK 원시 맥락으로 수집합니다. 도로 매칭·제한속도 적용 도로·확정 회전과 비상등 의미는 아직 연결하지 않아 해당 정식 평가 항목은 미평가입니다. 합성 결과와 실제 입력 결과는 화면과 로그에서 분리합니다.

장시간 주행 기록, 프로세스 재시작 복구, 장기 보관/내보내기, 서버 평가 API는 후속 작업입니다. 주행 중 UX·수집 서비스는 [주행 수집 서비스](driving-service.md)에 설명합니다. 원시 데이터·독립적인 정답을 이용해 오탐·누락·미평가율과 차량별 입력 품질을 검증한 뒤 평가 범위를 확대해야 합니다.

## 로컬 검증 결과 (2026-11-14)

- 순수 JVM 테스트 30개 통과: 지속시간·히스테리시스, 제한속도 유효기간/도로 불일치, 관측 공백·중복/역순 시각, 알려진 가감속, 방향지시등 준비와 미평가, 회전 검출 범위, 재생 결정성과 세션 격리.
- 합성 콘솔 재생과 에뮬레이터 앱에서 기본 시나리오의 복습 이벤트 4건을 확인했습니다.
- Docker APK 빌드 및 Android Lint 통과. Lint 오류 0건, 기존 버전/targetSdk/백업 설정 관련 경고 13건입니다.
- Pleos API 34 에뮬레이터의 P 기어·속도 0 상태에서 AAOS 차량 속도 권한 요청/허용 후 10초 수집을 실행했습니다. 실제 속도 표본 58개, 간격 100~207ms, 가감속 계산 가능 구간 9,797ms를 확인했습니다.
- 실제 입력 결과에서 속도 관리는 도로·제한속도 누락으로, 방향지시등은 회전 관측 미구현으로 미평가되는 것을 확인했습니다. 합성 결과를 실제 주행 결과로 표시하지 않았습니다.
- 이 결과는 입력·규칙·화면 연결 검증입니다. 실차 주행 정확도, 차선/신호/주변 객체 접근, 장시간 기록 안정성은 아직 검증하지 않았습니다.

## v0.3: 에뮬레이터 센서 수집과 복합 맥락

디버그 APK는 Vehicle SDK 2.3.2의 19개 공개 도메인(Brake, CarInfo, Display, Door, DrivingMode, EvBattery, Fuel, HVAC, Light, Odometer, Safety, Seat, SideMirror, SteeringWheel, Tire, Toll, TurnSignal, Window, Wiper)을 조사합니다. 공식 샘플의 공개 인터페이스 탐색 방식을 따르며, capability 응답이 읽기 권한을 제공한 항목만 조회/구독합니다. 영역은 capability가 돌려준 실제 영역만 사용합니다. 차량 제어 호출, InternalApi, private reflection, VIN/CRN, 공식 샘플에서 차단한 비공개/폐기 API는 제외합니다. 한 채널 실패가 다른 도메인 수집을 막지 않습니다.

항목별 PROBING / SUBSCRIBED / READABLE / LIVE / UNSUPPORTED / PERMISSION_DENIED / TIMEOUT / ERROR / SKIPPED / NO_PUBLIC_SDK를 기록합니다. 구독 등록과 실제 콜백 수신을 구분합니다. 광범위 SDK 진단 및 추가 권한/위치·내비 의존성은 debug에 제한하며 release의 전용 속도/조향 어댑터는 유지합니다.

복합 분석은 급조향·반복 조향·급감속 이벤트의 중앙 시각에 **과거의 신선한** 속도, 기어, 브레이크, 방향지시등, 크루즈 관측을 맞춥니다. 속도는 기존 Timeline 검증(역순/중복/결측/공백/1초 신선도)을 따르고 기타 상태는 2초 미만만 사용합니다. 동일 시각 충돌, 무효 관측, 수집 상한 도달 시 해당 증거를 사용하지 않습니다. 결과는 정차 중 조작, 후진, 크루즈 동작 맥락, 방향지시등 동반 조향, 제동 동반 조작, 무신호 반복 보정 후보, 입력 모순, 미확인으로 구분합니다. 특정 시각의 동시 관측 설명이며 사건 전체 원인이나 운전자 책임을 확정하지 않습니다. 크루즈 ACTIVATED는 횡방향 조향 보조를 의미하지 않습니다.

차로 중심/경계나 검증된 차로 기준 위치가 없으므로 lanePositionKnown은 false이고 차로 유지 항목은 미평가입니다. 조향·속도·일반 위치만으로 실제 차선 이탈을 검증했다고 표시하지 않습니다. 공조·좌석·연료 등은 원시 맥락으로 보존하지만 임의의 점수 가중치로 쓰지 않습니다.

주행 전체의 SDK 관측 수 상한은 두지 않습니다. 개별 복합 모델은 최대 64필드·중첩 3단계·컬렉션 32항목으로 요약하고, 지원 영역도 최대 16개를 조사합니다. ## 주행 기록 API와 서버 업로드

완료된 실제 SDK 수집과 독립 시나리오의 자동 분석 결과를 공통 API로 전송한다. 단순 예제 재생·수동 분석·저장본 복습은 새 주행을 만들지 않는다. 원시 SDK/위치 표본 전체 대신 `TraceReplay.summary`의 평가 항목·수치·환경 출처·원본 사건·묶음 코칭을 저장한다. 서버는 클라이언트가 계산한 결과를 보관하며 운전 정확도를 재인증하지 않는다.

OpenAPI 원본은 `packages/contracts/openapi/routy.yaml`이며 TypeScript 모델과 Kotlin API 클라이언트를 생성한다. 전송 형식은 schemaVersion 1이고 origin은 LIVE 또는 SYNTHETIC이다. 엔진/기본 규칙/환경 규칙 버전, UTC 시작·종료 시각과 durationMs를 함께 보관한다. 보고서 내부 startMs/endMs는 세션의 monotonic 시각이며 UTC와 섞지 않는다. 합성 시나리오의 UTC 구간은 첫 완료 분석 시각에서 합성 길이를 뺀 추정값이다. 같은 실행의 재전송은 최초 값 그대로 사용한다.

| API | 동작 |
|---|---|
| POST `/api/vehicle-installations` | 로컬에서 먼저 만든 설치 UUID·256비트 인증키 등록. 동일 인증은 200, 신규는 201, 다른 키로 덮어쓰기는 409 |
| PUT `/api/driving-records/{sessionId}` | 완료 기록 최초 저장 201, 같은 내용 재전송 200, 같은 세션의 다른 내용은 409 |
| GET `/api/driving-records` | 해당 설치의 수신 시각 역순 목록. limit 1~50, nextCursor 기반 다음 페이지 |
| GET `/api/driving-records/{sessionId}` | 해당 설치가 올린 전체 평가 스냅샷. 다른 설치 기록은 404 |

Prisma의 VehicleInstallation은 인증키 SHA-256만 저장하고 DrivingRecord는 설치/세션 복합 유일 제약, JSONB 요약 보고서, 정규화된 payloadHash와 버전/시각 메타데이터를 저장한다. 동시 업로드도 DB 유일 제약으로 한 건만 생성한다. 단일 요약 본문은 최대 2MiB이며 형식·시각·보고서 메타데이터 일치·JSON 깊이/크기를 검사한다. 장시간 기록의 전체 상세는 DrivingRecordPart에 작은 조각으로 저장하고 전체 해시 검증 후 확정하며 스트리밍으로 내려받는다. 기록 길이는 BIGINT로 저장하며 24시간 상한을 두지 않는다. 상세·목록·업로드는 `Bearer 설치UUID.인증키`가 필요하며 응답은 no-store이다. 인증키는 응답·로그·보고서에 넣지 않는다.

현재 소유 범위는 게스트 차량 설치다. 사용자 로그인, 스마트폰 계정에 차량을 연결하는 절차, 인증키 교체·폐기는 후속 단계다. 스마트폰에 차량 설치 인증키를 복사하는 방식으로 계정 연결을 대신하지 않는다. 운영 외부 노출 전 가입/등록 요청 제한 등 운영 정책도 별도로 설정한다.

차량 앱은 `no_backup/driving-records/{sessionId}.json`에 불변 전송 본문을 먼저 원자적으로 저장한다. SDK 수집마다 UUID를 만들고 시나리오는 runId를 사용한다. 인증 정보는 별도 `no_backup/vehicle-installation.json`에 보관한다. 앱 재시작 후 같은 파일을 읽으며 대기 항목을 새 UUID로 바꾸지 않는다. 서버 저장 응답의 세션 ID를 확인한 뒤 SENT와 서버 영수증을 기록한다. 네트워크 실패로 응답을 못 받아도 같은 세션을 재전송하므로 중복 저장되지 않는다.

[WorkManager](https://developer.android.com/jetpack/androidx/releases/work) 2.12.0으로 네트워크 연결 조건과 30초부터의 지수 백오프 재시도를 예약한다. 서버 연결 실패·408·429·5xx는 자동 재시도하고, 다른 4xx는 FAILED로 남겨 확인을 요청한다. 화면의 재전송 버튼은 실패 항목을 다시 대기로 돌리고 지연된 작업을 즉시 다시 예약한다. 대기·실패 기록을 자동 삭제하지 않으며 미전송 항목은 최대 200개다. 전송 완료 사본도 현재 유지한다. 장기 보관/정리 정책은 후속 작업이다. Release 빌드는 기존 HTTPS 서버 주소 검사를 따른다.

개발 DB는 `pnpm --filter @routy/web db:deploy`로 적용한다. 새 개발 컨테이너는 Prisma 생성·마이그레이션 후 서버를 시작한다. 운영 Compose는 migrate 서비스 성공 후 web을 시작한다. 프로덕션 이미지는 Prisma 클라이언트를 빌드 중 생성하며 DB를 읽는 코드는 Capacitor 정적 빌드에서 제외된다.


## MVP 계정과 일회용 차량 연결

차량 한 대와 계정 하나를 일대일로 연결한다. 사용자 웹은 이메일·10자 이상 비밀번호로 가입/로그인하고 HttpOnly·SameSite=Lax 세션 쿠키를 사용한다. 운영 쿠키는 Secure이며 세션은 30일 후 만료되고 로그아웃 시 서버에서도 폐기한다. 비밀번호는 개별 salt를 사용하는 scrypt, 세션/차량 인증키와 연결 코드는 SHA-256으로 저장한다. 비밀번호 재설정·이메일 소유 확인·차량 계정 변경은 이번 MVP 범위에 포함하지 않는다.

차량의 설치 인증은 그대로 유지한다. 차량이 POST `/api/vehicle-pairings`로 발급한 8자리 코드는 5분 동안 유효하며 QR에는 일회용 코드와 사용자 웹 주소만 넣는다. 웹에서 로그인 후 preview로 대상 차량과 계정을 확인하고 명시적으로 claim해야 연결된다. 재발급은 기존 PENDING 코드를 취소하고, claim은 직렬화 트랜잭션과 DB 유일 제약으로 한 번만 소비한다. 코드 검증/발급과 로그인 요청에는 DB 기반 시도 제한을 둔다. 브라우저 변경 요청은 같은 출처인지도 검사한다.

연결 뒤 `/api/account/vehicle`과 `/api/account/driving-records`는 계정 세션으로 소유 차량과 기록만 반환한다. 다른 계정의 기록은 404이며 차량 설치 인증키를 웹으로 복사하지 않는다. 해당 설치의 기존 완료 기록도 연결된 계정에 표시된다. 원시 설치 인증을 사용하는 기존 업로드 API는 변경하지 않는다.

`ROUTY_PUBLIC_WEB_ORIGIN`은 QR에 넣을 경로 없는 웹 주소다. 로컬 기본값 `http://localhost:3000`은 같은 노트북에서 코드로 연결을 검증하기 위한 값이다. 실제 스마트폰에서 QR을 열려면 그 기기에서 도달 가능한 HTTPS origin으로 설정하고 해당 서버를 제공해야 한다. 현재 개발 Compose의 호스트 바인딩은 loopback을 유지한다. 외부 배포는 별도 작업이며 정적 Capacitor 네이티브 앱의 교차 출처 로그인 브리지는 아직 구성하지 않는다. 이번 사용자 웹은 스마트폰·노트북 브라우저에서 같은 출처 세션으로 동작한다.
