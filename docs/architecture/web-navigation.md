# 웹 화면과 URL

기존에는 `/`에서 React 상태만 바꿔 화면을 전환했으므로 브라우저 히스토리에 화면이 기록되지 않았고 새로고침하면 홈으로 돌아갔습니다. 현재는 Next.js App Router의 주소를 화면 상태의 기준으로 사용합니다.

| 화면 | 주소 |
| --- | --- |
| 내 연습 | `/` |
| 주행 기록 목록 | `/records` |
| 주행 평가 상세 | `/records?session=<세션 UUID>` |
| 차량 연결 | `/connect` |
| QR로 차량 연결 | `/connect?code=<연결 코드>` |
| 로그인 | `/login?next=<원래 화면>` |
| 회원 가입 | `/signup?next=<원래 화면>` |

일반 화면 이동과 기록 행은 Next Link를 사용합니다. 목록 및 상세를 주소에서 복원하고 해당 기록을 로그인 계정의 API로 다시 조회합니다. 데이터가 준비될 때까지 로딩 상태를 표시하며, 없는 기록이나 잘못된 ID는 홈으로 전환하는 대신 오류를 안내합니다. 이전 주소의 조회가 늦게 끝나더라도 새 주소에 다른 기록을 표시하지 않습니다.

`(routy)` 공통 레이아웃이 화면을 유지하고 각 정적 페이지가 URL과 메타데이터를 정의합니다. `useSearchParams`는 Suspense 안에서 사용합니다. 상세 ID는 쿼리로 전달하므로 미리 알 수 없는 모든 세션에 대해 동적 페이지를 생성할 필요 없이 Capacitor 정적 내보내기에서도 동작합니다. 웹과 앱 모두 `/records`, `/connect`, `/login`, `/signup` 페이지를 빌드합니다.

로그인 후 원래 주소로 복귀합니다. `next`는 앱이 소유하는 화면으로 제한하고 외부 URL, 스크립트, 인증 화면으로의 재귀 복귀 및 임의 쿼리는 허용하지 않습니다. 기존 차량 앱이 발급하는 `/?connect=...` 주소는 코드를 유지하며 새 연결 주소로 교체합니다. 인증 토큰은 URL에 넣지 않습니다.

브라우저 뒤로가기와 앞으로가기는 Next.js의 히스토리를 따릅니다. 화면의 상위 이동 버튼은 직전에 해당 상위 화면에서 진입했다면 뒤로가기를 사용하고, 직접 상세 주소를 연 경우에는 안전한 상위 주소로 교체합니다.

## 검증

`pnpm --filter @routy/web test:navigation`은 직접 주소 및 새로고침 URL의 응답, 상세와 QR의 로그인 복귀 주소 보존, 외부 복귀 주소 차단을 확인합니다. Driving record API 워크플로에도 추가했습니다.

실제 브라우저에서는 임시 로컬 계정과 합성 기록으로 상세 직접 접속 후 로그인, 상세 새로고침, 홈 → 목록 → 상세의 뒤로 및 앞으로 이동, 차량 연결 새로고침, 기존 QR 코드 및 로그인 주소의 새로고침과 취소 복귀를 확인했습니다. 모바일 폭에서도 링크의 표시와 동작을 확인했습니다. 운영 웹 빌드와 Capacitor 정적 빌드를 별도로 검증합니다.

NAS 재배포 후 웹에 반영됩니다. 이미 배포된 스마트폰 앱에는 새 네이티브 빌드로 포함해야 합니다.
