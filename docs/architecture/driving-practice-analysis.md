# 주행 행동·도로 맥락·복습 피드백 v0.4

`DrivingSession → PracticeInputs → PracticeAnalyzer / RoadMatcher → 기존 평가 규칙 → LearningFeedbackBuilder → EvaluationReport`

같은 입력에서 행동 검출, 지도 매칭, 평가 범위, 복습 피드백을 재현합니다. 규칙 버전은 `experimental-0.4`, 엔진은 `0.4.0`입니다. 수치 기준은 시연용 실험 설정이며 실차 정확도나 법적 판단 기준이 아닙니다.

## 행동 검출과 방향지시등 평가

- 위치·헤딩과 속도의 연속 구간을 검사합니다. 단절·중복/역순 시각·알 수 없는 시각 기준·GPS 이동과 속도의 모순·위치 점프에서는 행동을 이어 붙이지 않습니다.
- 헤딩 변화가 시작된 구간을 모으고 안정 구간 1초를 관측한 뒤 완료합니다. 끝이나 공백에서 끊긴 조작은 `INCOMPLETE`입니다.
- 좌/우회전 확정에는 40~135도 방향 변화, 알려진 위치 정확도, 고유하게 매칭된 전후 도로, 도로 그래프의 연결 지점이 함께 필요합니다. 헤딩 입력 기준은 북쪽 0도·시계 방향 증가입니다.
- 같은 도로에서 지도 형상과 헤딩이 함께 변하면 커브입니다. 방향이 변했다 돌아오고 옆 방향 이동이 있어도 차로 변경은 **후보**입니다. 후보에는 위치 정확도보다 큰 이동과 직선 도로 근거를 요구하며 경계 통과를 확정하지 않습니다.
- 직진 맥락·저속 조작·후진을 구분합니다. 방향지시등은 행동 검출의 근거로 사용하지 않습니다.
- 확인된 회전을 기존 방향지시등 규칙에 자동 연결합니다. 호출자가 이미 확인된 회전을 주면 중복 추가하지 않습니다.

## 도로 맥락과 지도 계약

`RoadNetwork`는 개정 번호, 출처(`SYNTHETIC` / `VERIFIED_MAP`), 도로 목록을 받습니다. 도로는 ID·입구/출구 노드·방향이 있는 좌표 형상·선택적 제한속도(m/s)·단조 시각 기준 유효기간·양방향 여부를 갖습니다.

위치에서 선분까지의 거리와 진행 방향으로 도로 후보를 찾습니다. 병렬 도로가 모호하면 `AMBIGUOUS`이며 위치 정확도가 낮을수록 모호성 범위를 넓힙니다. 지리적으로 선이 교차해도 노드가 연결되지 않으면 회전 근거가 아닙니다. 모호하거나 만료된 도로 및 잘못된 지도에서 제한속도를 이전 값으로 유지하지 않습니다.

고유한 매칭과 유효한 제한속도가 있을 때 `RoadContext`를 만들어 기존 속도 관리 규칙에 전달합니다. 전후 국소 도로 방향 변화로 커브 맥락을 제공합니다. 합성 지도는 `LIVE`/`RECORDED` 평가에 적용하지 않습니다.

### 실제 SDK와 지도 입력의 경계

- FusedLocation **업데이트** 또는 NaviHelper 현재 위치 이벤트를 정규화합니다. 마지막 알려진 위치 캐시는 새 궤적으로 쓰지 않습니다.
- native 헤딩 단위/기준과 confidence→미터 정확도 변환을 검증하지 못했으므로 그대로 신뢰하지 않습니다. 실제 좌표 이동이 2m 이상일 때 과거 좌표에서 진행 방향을 계산하고 accuracy는 알 수 없음으로 유지합니다.
- 현재 에뮬레이터처럼 위치가 고정되면 실제 회전이 검출되지 않습니다. 실제 위치 정확도와 실도로 형상/연결 지점/제한속도를 공급하는 어댑터가 있어야 실제 주행의 지도 기반 확정 평가가 가능합니다.
- NaviHelper의 경로 ID를 도로 ID로 바꾸거나, 적용 도로가 없는 제한속도 이벤트를 과속 평가에 쓰지 않습니다.
- Vehicle SDK의 OFF/LEFT/RIGHT를 신호 선택으로 연결합니다. 비상등 상태가 알려지지 않으면 신호 사용의 확정 평가는 보류합니다. 합성 시연은 비상등 관측 여부도 명시합니다.

앱은 선택적으로 앱 전용 `files/road-network.json`을 읽습니다. 파일이 없거나 잘못되면 지도 없이 수집·관측 평가를 계속합니다. 형식은 `PracticeCodec.encodeNetwork()`의 구조에 `effectiveFromEpochMs`, `expiresAtEpochMs`를 추가한 공급자 데이터입니다. 각 도로의 `validUntilMs`는 공통 UTC 만료 시각에서 단조 시각으로 변환합니다.

실제 파일은 `provenance: VERIFIED_MAP`을 요구합니다. 이는 **호출자가 검증한 출처를 선언하는 계약**이며 엔진이 공급자를 인증한다는 뜻은 아닙니다. 세션 시작 후에 효력이 생긴 지도는 과거 구간에 적용하지 않습니다. 이미 만료된 지도를 읽어도 유효기간을 살리지 않습니다. 외부 지도 서비스·인증 키·온라인 다운로드는 포함하지 않았습니다.

## 품질과 이벤트 묶음

`practice.quality`에는 궤적·도로 매칭·가감속 입력·조향 입력·방향지시등 선택의 표본 수, 사용 가능한 시간, 전체 시간과 제외 사유가 있습니다. 관측 비율은 정확도 확률이나 운전 점수가 아닙니다. `SUPPORTED / LIMITED / INSUFFICIENT`는 근거의 상태입니다.

같은 종류·같은 맥락의 가까운 이벤트를 복습 항목으로 묶고 원본 이벤트와 근거를 보존합니다. 정차/후진/제동/크루즈·커브를 구분합니다. 전체 이벤트를 포함하는 직진 근거가 있어야 ‘직진 구간의 반복 보정’이라고 설명합니다. 맥락이 다른 이벤트를 하나의 운전 실수로 합치지 않습니다.

## 학습 피드백

`feedback`는 다음 연습 목표·상황 복습·상황 참고·데이터 확인으로 나뉩니다. 각 항목에는 시간, 관측 내용, 다음 연습 제안, 근거, 누락 정보와 원본 이벤트 종류가 있습니다. 우선순위는 복습 순서이며 위험도 점수가 아닙니다.

- 확인된 좌회전 + 늦은 신호 → ‘회전 전 방향지시등 준비 시간이 짧았어요’.
- 확인된 직진 + 반복 조향 → ‘직진 구간에서 조향 보정이 반복됐어요’.
- 동일 도로의 곡률/방향 변화 → ‘커브를 따라 진행 방향이 바뀌었어요’.
- 제동 중 조향 → ‘제동과 조향이 함께 관측됐어요’. 장애물·끼어들기 원인은 확인하지 않습니다.
- 부족한 관측 → ‘관측이 부족한 항목은 평가를 보류했어요’.

앱은 합성 시연과 실제 기록을 구분하고 복습 피드백을 먼저 보여줍니다. 판단 근거와 상세 SDK 진단은 따로 펼칩니다. 주행 중 진단 화면 사용 제한은 우회하지 않습니다.

## 자동 검증과 기록 호환

기존 16개에 `practice-v1.json`의 18개를 추가했습니다. 새 시나리오는 확정 회전/`RoadContext`를 미리 넣지 않고 좌표·헤딩·지도에서 시작합니다. 좌/우회전, 신호 정상/미사용/늦음/반대/중간 해제, 커브, 차로 변경 후보, 주차·후진, 모호한 지도, 위치 공백, 미완료 조작, 비상등 미확인, 직진 보정, 매칭 제한속도 초과를 검사합니다.

```powershell
.\infra\pleos\test-scenarios.ps1
.\infra\pleos\test-scenarios.ps1 -Emulator
```

0.4 기록에는 위치·지도·정규화 신호·명시적 회전·품질·행동·피드백 및 기본 설정 서명을 보존합니다. 재생 시 전체 분석을 다시 계산해 비교합니다. 기본 설정만 지원하며 다른 설정은 명시적 지원 없이 재생하지 않습니다. 기존 0.3/experimental-0.3 기록은 옛 형식으로 읽고 복합 맥락을 비교하는 호환 경로를 유지합니다.

차로 유지, 신호등 대응, 차간거리 항목은 여전히 미평가입니다. 차로 변경 후보도 차선 경계 관측이나 운전자 책임 판정으로 승격하지 않습니다.

Virtual Console의 환경 모델을 보강해 네 기능을 구현하는 방법은 [가상 주행 환경과 평가 구현 계획](driving-environment-plan.md)에 정리합니다. 현재 구현 상태와 향후 입력·평가 계획을 구분합니다.
